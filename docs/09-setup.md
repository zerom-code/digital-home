# 09. Развёртывание с нуля

Пошагово: от пустого проекта Supabase до приложения на телефоне.
Занимает около получаса, ничего платного не требуется.

---

## 1. Проект Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте
   проект. Регион берите ближе к пользователям — для Украины это Франкфурт
   (`eu-central-1`).
2. Придумайте и **сохраните пароль к базе**: восстановить его нельзя, только
   сбросить.
3. Дождитесь, пока проект поднимется (пара минут).

Из раздела **Project Settings → API** понадобятся два значения:

| Что | Где | Секретное? |
|---|---|---|
| `Project URL` | API Settings | нет |
| `anon public` ключ | API Settings | **нет** — публичный по замыслу, доступ ограничивает RLS |
| `service_role` ключ | API Settings | **да** — на клиент не попадает никогда |

## 2. Схема базы

### Вариант А — через веб-интерфейс (проще)

Откройте **SQL Editor** в панели Supabase и выполните по очереди, строго в
этом порядке:

```
supabase/migrations/0001_schema.sql
supabase/migrations/0002_rls.sql
supabase/migrations/0003_rpc.sql
supabase/migrations/0004_storage.sql
```

Затем сгенерируйте и выполните справочник категорий:

```bash
node scripts/build-seed.mjs
# получившийся supabase/seed/categories.sql — тоже в SQL Editor
```

### Вариант Б — через Supabase CLI

```bash
npm install -g supabase
supabase link --project-ref <ID проекта>
supabase db push
psql "$DATABASE_URL" -f supabase/seed/categories.sql
```

### Проверка

```sql
select count(*) from public.item_categories;   -- 99
select count(*) from pg_policies
 where schemaname in ('public','storage');     -- 51
```

Если политик меньше — какая-то миграция не прошла целиком. Не запускайте
приложение до того, как это исправите: **RLS здесь единственный слой
авторизации**, и без него данные всех семей видны всем.

Миграция `0004_storage.sql` уже создаёт приватный бакет `docs` и политики

галочку «Public bucket». Политики уже наложены миграцией.

## 3.5. Уведомления и распознавание (фаза 2)

### Ключи VAPID для push

```bash
npx web-push generate-vapid-keys
```

Публичную часть — в `.env` как `VITE_VAPID_PUBLIC_KEY`, приватную — только в
секреты Supabase:

```bash
supabase secrets set VAPID_PUBLIC_KEY=... VAPID_PRIVATE_KEY=... \
                     VAPID_SUBJECT=mailto:you@example.com \
                     CRON_SECRET="$(openssl rand -hex 16)"
supabase functions deploy send-push --no-verify-jwt
```

`CRON_SECRET` нужен потому, что функция ходит под служебной ролью: без него
её мог бы дёрнуть кто угодно.

### Расписание

Миграция `0005` заводит две задачи `pg_cron` — ежедневную генерацию задач и
еженедельную чистку корзины. **Расширение надо включить в панели Supabase**
(Database → Extensions → `pg_cron`), иначе миграция это тихо пропустит — так
задумано, чтобы она накатывалась и на обычный Postgres.

Отправку уведомлений вызываем из расписания через `pg_net`:

```sql
select cron.schedule(
  'domovoy-send-push', '*/15 * * * *',
  $$ select net.http_post(
       url := 'https://<проект>.supabase.co/functions/v1/send-push',
       headers := '{"x-cron-secret": "<CRON_SECRET>"}'::jsonb
     ) $$
);
```

### Распознавание шильдиков

```bash
supabase secrets set OPENAI_API_KEY=sk-...
supabase functions deploy ai-extract-nameplate
```

Ключ живёт только здесь и **никогда** не получает префикс `VITE_`
([ADR-009](07-decisions.md)). По умолчанию распознавание выключено:
включается в приложении, «Ещё» → «Распознавание с фото», с явным согласием.

## 4. Вход в приложение

**Authentication → Providers:**

- **Email** — включён по умолчанию, ничего настраивать не нужно.
  Приложение шлёт ссылку для входа (`signInWithOtp` + переход по ссылке из
  письма), а не код из шести цифр — стандартное письмо Supabase уже
  содержит кнопку «Sign in» и работает без всякой настройки.

  > На бесплатном плане Supabase текст письма нельзя отредактировать без
  > своего SMTP-сервера — форма в **Email Templates** там просто неактивна.
  > Поэтому приложение и не требует кода из письма: код показать было бы
  > негде. Если позже подключите свой SMTP (например, Resend) — сможете
  > поменять оформление письма, но менять код приложения для этого не
  > придётся: главное, чтобы в письме осталась ссылка `{{ .ConfirmationURL }}`.

- **Google** и **Apple** — по желанию, каждому нужен свой Client ID и Secret
  из консоли соответствующего разработчика.

**Authentication → URL Configuration:**

- `Site URL` — адрес приложения (для разработки `http://localhost:5173`)
- `Redirect URLs` — добавьте и локальный адрес, и боевой домен

Без этого вход через Google и Apple вернёт человека в никуда.

## 5. Приложение

```bash
cp .env.example .env
```

Заполните в `.env`:

```
VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
VITE_APP_URL=http://localhost:5173
```

`OPENAI_API_KEY` и прочие серверные секреты в этот файл **не попадают** —
они задаются только в секретах Supabase, когда дойдёт до фазы 4 (ADR-009).

Дальше:

```bash
npm install
npm run icons       # иконки для установки на домашний экран
npm run typecheck
npm run test
npm run dev
```

Откройте `http://localhost:5173`.

## 6. Первый проход

Проверьте сценарий целиком — он же является критерием готовности фазы 1:

1. **Вход.** Введите почту и пароль → «Создать аккаунт». Дальше входите этой
   же парой.

   Второй способ — «Войти по ссылке на почту»: письмо → кнопка «Sign in» →
   вкладка с приложением сама покажет, что вы вошли.

   > **На iPhone в установленном приложении пользуйтесь паролем.** Ссылка
   > из письма там откроется в Safari и войдёт только в Safari: iOS держит
   > хранилища PWA и браузера полностью раздельно ([ADR-010](07-decisions.md)).
   > Приложение предупреждает об этом прямо на экране входа.
2. **Онбординг.** Назовите дом, выберите шаблон «2-комнатная».
   Должны появиться пять комнат с техникой.
3. **Вещь за 30 секунд.** Кнопка «＋» в центре нижней панели → введите
   название → «Готово». Кнопка обязана быть активной сразу после первого
   символа: больше ничего заполнять не требуется.
4. **Фотография.** Откройте вещь, «Изменить» — или добавьте новую с камерой.
   На телефоне камера должна открыться сразу.
5. **Гарантия.** Укажите дату покупки и срок — в карточке появится обратный
   отсчёт по-русски: «Действует ещё 1 год 4 месяца».
6. **Поиск.** Строка сверху главного экрана: ищите по названию, модели,
   серийнику. Проверьте забытую раскладку: `[jkjlbkmybr` находит холодильник.
7. **Семья.** «Ещё» → «Семья» → «Создать ссылку» → «Поделиться». Откройте
   ссылку в другом браузере или на другом телефоне, войдите под другой
   почтой — должна открыться та же квартира.
8. **Установка.** На Android появится системное предложение установить,
   на iPhone — инструкция «Поделиться → На экран „Домой“».
9. **Офлайн.** Включите авиарежим и перезапустите приложение: комнаты и вещи
   должны открыться из кеша, сверху появится полоска «Работаем офлайн».
   Добавьте вещь и загрузите документ — полоска сменится на «N изменений
   отправлю позже». Выключите авиарежим: за минуту очередь уйдёт, полоска
   исчезнет, данные появятся на втором устройстве.
10. **Документы.** В карточке вещи добавьте инструкцию файлом и ссылкой.
    Файл в очереди помечается «Загружается» — это нормально.
11. **Задачи.** Укажите вещи дату покупки и срок гарантии так, чтобы он
    заканчивался в ближайший месяц. Вкладка «Задачи» → «Пересчитать» —
    появится напоминание. Закройте его: если у задачи задано повторение,
    сразу появится следующая.
12. **Уведомления.** «Ещё» → «Напоминания». На Android разрешение
    спрашивается сразу; **на iPhone пункт будет неактивен, пока приложение
    не добавлено на домашний экран** — так работает iOS, это не ошибка.
13. **Распознавание.** «Ещё» → «Распознавание с фото» → согласие. Затем в
    карточке вещи без модели появится блок «Распознать табличку»:
    сфотографируйте шильдик, проверьте поля со значком ✨ и сохраните.

## 7. Публикация

PWA без HTTPS не работает даже наполовину: без него браузер не регистрирует
service worker, а без него нет ни офлайна, ни установки на экран, ни push
(docs/05-architecture.md). Ниже — путь без домена и без своего сервера, и
общий путь для любого другого хостинга.

### 7.1. GitHub Pages (рекомендую, если нет своего домена)

Бесплатный HTTPS сразу, без покупки домена и без настройки сертификатов.
Уже настроено в репозитории — `.github/workflows/deploy-pages.yml` собирает
и публикует приложение при каждом пуше в рабочую ветку.

**Разово, один раз:**

1. **Секреты.** Repo → **Settings → Secrets and variables → Actions →
   New repository secret**, добавить два:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

   (те же значения, что в вашем `.env`; ключ публичный по замыслу, но хранить
   его в секретах репозитория, а не в файле workflow, всё равно правильнее)

2. **Источник Pages.** Repo → **Settings → Pages** → в «Build and
   deployment» → **Source: GitHub Actions** (не «Deploy from a branch»).

3. Отправить пуш в рабочую ветку — сборка запустится сама. Прогресс: вкладка
   **Actions** в репозитории. После первого успешного прогона приложение
   будет по адресу `https://<владелец>.github.io/<репозиторий>/`.

**После первого деплоя, в Supabase:**

**Authentication → URL Configuration → Redirect URLs** → добавить
`https://<владелец>.github.io/<репозиторий>/`.

Дальше просто отправляйте изменения в рабочую ветку — задеплоится само.
Локальный `.env` эта публикация не трогает: сборка в CI берёт значения из
секретов репозитория, а не с вашей машины.

> **Почему в приложении хэш-роутер** (`/#/item/abc`, а не `/item/abc`):
> GitHub Pages не умеет на сервере «доигрывать» прямую ссылку на глубокий
> путь — вернёт 404. С хэшем всё после `#` браузер обрабатывает сам, сервер
> его вообще не видит. Подробности и почему это не конфликтует со входом
> через Supabase — [ADR-017](07-decisions.md).

### 7.2. Любой другой хостинг (свой сервер, Cloudflare Pages, Netlify, Vercel)

```bash
npm run build      # результат в dist/
```

Обязательные настройки хостинга:

- **Заголовок для service worker**: `Cache-Control: no-cache` на `sw.js`.
  Иначе люди останутся на старой версии навсегда — браузер закеширует сам
  механизм обновления.
- **HTTPS обязателен** — см. выше.
- SPA-переадресация (все пути на `index.html`) **не обязательна**: из-за
  хэш-роутера сервер и так видит только один и тот же путь при любой
  странице внутри приложения.

После первого деплоя не забудьте:

1. добавить боевой адрес в `Redirect URLs` в Supabase;
2. поменять `VITE_APP_URL` — от него зависят ссылки-приглашения;
3. если приложение живёт не в корне домена (поддиректория) — задать
   `VITE_BASE_PATH` при сборке, как это делает `deploy-pages.yml` для
   GitHub Pages.

## 8. Проверка базы локально

Отдельно от облака: миграции и тесты изоляции семей гоняются на обычном
PostgreSQL 16+, без Docker и без Supabase.

```bash
bash scripts/db-test.sh
```

Скрипт создаёт временную базу, подменяет схемы `auth` и `storage`, накатывает
все миграции и справочник, прогоняет `supabase/tests/rls_test.sql` и удаляет
базу за собой. Это же выполняется в CI на каждый коммит.

Тесты проверяют главное: что пользователь одной семьи не видит **ни одной
строки** другой, что гость не может писать, что политики не уходят в
рекурсию и что приглашения нельзя использовать повторно.

## Если что-то не так

| Симптом | Причина |
|---|---|
| Приложение падает на старте с сообщением про переменные | Не заполнен `.env`, или dev-сервер не перезапущен после правки |
| Видно чужие данные | Не прошла `0002_rls.sql`. Проверьте число политик — их должно быть 51 |
| `infinite recursion detected in policy` | Политика на `household_members` создана без `is_household_member` |
| Ссылка из письма не переводит в приложение | `Redirect URLs` в Supabase не содержит адрес приложения, или `VITE_APP_URL` не совпадает с адресом, на котором открыт `.env` |
| Письмо не приходит | Проверьте папку «Спам»; Supabase на бесплатном плане ограничивает частоту писем — подождите минуту между запросами |
| Фотографии не грузятся | Бакет `docs` не создан или сделан публичным |
| На iPhone нет предложения установить | Так и должно быть: iOS не поддерживает `beforeinstallprompt`, приложение показывает инструкцию вручную |
| Прямая ссылка на вещь даёт 404 | На хостинге не настроена SPA-переадресация |
